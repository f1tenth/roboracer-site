Recurring structural traps found on the 2026-08-20 audit (commit 3273a8a / merge-base 4ea2e09) that are easy to miss on a quick read and should be re-checked, not assumed unchanged, on the next audit:

- `src/pages/sections/` (About, GettingStarted, Registration, Resources, Rules, Timeline + `sections/assets/*`, ~30 MB) is a leftover race-microsite build that is not imported from anywhere reachable from `src/App.tsx`. It looks like part of the live site because the filenames shadow real top-level pages (e.g. `sections/About.tsx` vs `pages/About.tsx`) - always `grep -rln "sections/<Name>" src` before assuming it's dead, and check again each audit since it's a natural target for deletion that may already be gone.
- `public/data/publications.json` is written by the Python discover-papers/bibtex-migration pipeline (`scripts/discover_papers.py`, `scripts/migrate-bibtex.py`) but is **not fetched by any React component**. `/research` (`src/pages/Research.tsx`) instead fetches raw BibTeX directly from `raw.githubusercontent.com/f1tenth/roborace_publications/main/pub.bibtex` at runtime. Don't assume this JSON file's schema or freshness maps to what users see on `/research`.
- Two independent, hand-maintained route-string lists both control "alt chrome" (hidden/fullscreen nav+footer) and can drift apart: `src/components/Layout.tsx` (`isAltLayout`, `isHiddenRoute`) and `src/components/Footer.tsx` (`isAltFooter`, which only lists `/learn`/`/build`/`/course`, not `/chat`). Check both when a route's chrome behavior seems inconsistent.
- Directory-vs-JSON asset audits are high-yield here: `public/crew/`, `public/partners/`, `public/testimonials/` all have far more image files on disk than the corresponding `team_*.json`/`partners.json`/`testimonies.json` reference (54 MB / 47 files / 17 files orphaned respectively at time of writing). Always compute `all_files - referenced_files` per directory with a quick Python script rather than eyeballing `ls`.
- `@tsparticles/slim` and `@tsparticles/engine` are imported directly in `src/components/PoppingParticles.tsx` (itself dead code) without being declared in `package.json` — they only resolve because they're transitive deps of `tsparticles`/`@tsparticles/react`. Same pattern on branch `feat/assembly-viewer`: `RacecarAssembly.tsx` imports `three-stdlib` directly, also undeclared, resolving only as a transitive dep of `@react-three/drei`. Worth a `package.json` vs. actual-imports diff each audit, not just a "does it build" check — it builds today only by luck of hoisting.
- `motion` and `framer-motion` are both declared as direct dependencies at the same version; only `framer-motion` is ever imported (`NavBar.tsx`). They are the same underlying library under two npm package names — flag as redundant, not as "unused dependency" (removing the wrong one breaks the build).
- `git merge-tree $(git merge-base <a> <b>) <a> <b> 2>&1 | grep -i conflict` is a fast, read-only way to check whether an unmerged branch (e.g. `feat/assembly-viewer`) will merge cleanly into `main` or the current branch without checking it out — useful for the "sequencing" question in these audits.
