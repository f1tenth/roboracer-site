# Independent QA review: `/` (landing)

Reviewer pass, separate from the builder's self-QA at `docs/qa/landing.md` (that file is evidence of the builder's own process, not verified here as a source of truth). Branch `revamp/landing`, production build served via `vite preview` on `http://localhost:5198/`. Reviewed 2026-08-21.

## Verdict: FIX FIRST

The page is well-built: correct semantics, zero axe violations, zero console errors, all links resolve, complete reduced-motion and no-JS behavior, clean design-token usage, correct voice/content in almost every place checked. But two objective, checklist-violating, cheaply-fixable bugs should be fixed before this ships: an eager-autoplay duplicate-video bug that roughly triples first-load video weight, and a "poor"-tier layout shift on tablet. Neither requires touching the page's structure or visual language — this is not a redesign call.

## Blockers

1. **Highlights chapter double-loads and double-autoplays the same placeholder video, off-screen, uncapped by IntersectionObserver.** `HighlightReel` (`src/components/ui/HighlightReel.tsx`) renders `autoPlay` `<video>` for every item with no visibility gating. `Landing.tsx`'s two highlight items both point at `HERO_VIDEO.mp4_960` (`/media/hero/hero-fpv-loop-960.mp4`, 2,867,927 bytes) — the second is the explicit `TODO(content)` placeholder, which is fine as *content*, but as *code* it means two identical 2.8 MB videos autoplay simultaneously, below the fold, immediately on load, alongside the hero's own autoplaying video. Measured with Playwright network capture (`prefers-reduced-motion: no-preference`, networkidle): **initial-load transfer = 8.94 MB desktop / 8.95 MB tablet / 9.14 MB mobile**, of which **~8.0 MB (89%) is video**, split across three near-fully-downloaded video responses (206 Partial Content, ~97-98% of each file) despite `preload="metadata"` on every `<video>`. `ExplodedModel` in the same file already solves this correctly with an `IntersectionObserver` (`rootMargin: "600px"`) before mounting the R3F scene — `HighlightReel` needs the same treatment (or at minimum: don't render a live `<video>` for the still-placeholder second tile; use the poster only, the way the reduced-motion path already correctly does). Fix is small and localized; this is not a content problem, it's a loading-strategy gap.
   - Evidence: `docs/qa/landing/review/desktop.png` top network sample — `hero-fpv-loop-960.mp4` appears twice at 2800.7 KB each plus `hero-fpv-loop-1920.mp4` at 2595.3 KB, all status 206.

2. **Cumulative Layout Shift is "poor" on the tablet viewport: CLS = 0.327** (Core Web Vitals: >0.25 = poor; good is <0.1). Desktop (0.028) and mobile (0.060) are both comfortably good — only 768x1024 crosses the line. Measured via a `PerformanceObserver({type:'layout-shift', buffered:true})` injected before navigation. The shift (value 0.320, startTime ~450ms) sources to the hero's headline/lead wrapper (`DIV.relative mx-auto w-full max-w-content px...`). Root cause: `index.html` loads Space Grotesk/Manrope/JetBrains Mono via Google Fonts with `display=swap` and no fallback metric matching, so the fallback-font hero H1 reflows once the webfont swaps in; at exactly the `md`/768px hero-column width this changes the headline's line count enough to move everything below it. This directly contradicts CLAUDE.md's page Definition of Done ("no layout shift on load"). Fix is font-loading strategy (e.g. `size-adjust`/metric-matched `@font-face` fallback, or reserve min-height on the hero text block), not a page redesign.
   - Evidence: raw CLS entries captured in-session (not persisted as a file per scope, values quoted above are exact); visual pair `docs/qa/landing/review/tablet-t0.5.png` / `tablet-t3.png` for context (the shift itself resolves before the first 500ms capture, which is why the two frames look similar — the PerformanceObserver is the authoritative measurement here, not the screenshots).

## Should-fix

3. **Mobile hero/highlight video encode is larger than the desktop encode.** `hero-fpv-loop-960.mp4` = 2,867,927 bytes vs `hero-fpv-loop-1920.mp4` = 2,657,578 bytes. Because `<source media="(min-width: 768px)">` gates the 1920 file, phones (<768px) get the *smaller-resolution, bigger-file-size* encode — backwards for the audience most likely to be on a constrained connection. Re-encode the 960 at a lower bitrate.
4. **Brand name mis-cased in content that renders on this page.** `public/data/upcoming_events.json` titles read "Roboracer" (lowercase second r) for all three 2026 entries, including the spotlight event whose `title` renders verbatim in `NextRaceSpotlight`: "31st **Roboracer** Autonomous Racing Competition at the IEEE/RSJ...". `roboracer-content` voice rule: 'Write "RoboRacer" everywhere.' Visible in `docs/qa/landing/review/mobile-crop-nextrace.png`. One-line JSON fix, not a Landing.tsx change, but it's a homepage-visible brand-name typo.
5. **`rel="noreferrer"` instead of `rel="noopener noreferrer"`** on three external `target="_blank"` links: `NextRaceSpotlight.tsx` ("Register your team", "Rules and resources"), `PublicationCard.tsx` (paper links, e.g. the arXiv ForzaETH link), `TeamGrid.tsx` (team site link, currently unrendered). Functionally safe — `noreferrer` alone already blocks `window.opener` access in all current browsers — but inconsistent with every other external link on the page (which correctly carries `rel="noopener noreferrer"` via `Button`'s pass-through), and inconsistent with the literal checklist rule. Low severity, easy consistency fix.
6. **axe "incomplete" (not a violation): `aria-prohibited-attr`** on `NextRaceSpotlight`'s countdown wrapper: `<div aria-label="Time until the competition starts" class="flex gap-6">`. A bare `<div>` has implicit `role=generic`, which does not reliably expose `aria-label` to assistive tech. Recommend `role="group"` (or `role="timer"`) on that wrapper.
7. **Registration deadline carries an unresolved VERIFY caveat.** `NextRaceSpotlight` renders "Registration closes September 5, 2026" from `upcoming_events.json`'s `registration_deadline`. The `roboracer-content` skill states this date with an explicit caveat: "(may be extended, VERIFY before publishing a date)." Not a fabricated fact — it's the best-known date from Cedric — but worth a final confirm before/at ship since the page is publishing a specific, dated commitment to teams.

## Summary for Cedric

The rebuilt landing page is architecturally sound and matches the design system closely: correct tokens, correct motion vocabulary, zero axe violations, zero console errors, all links resolve, and reduced-motion/no-JS fallbacks are complete. Fix two things first: the Highlights section autoplays two full copies of the same 2.8 MB placeholder video off-screen with no visibility gating (push first load to ~9 MB, 89% video, when `ExplodedModel` right below it already shows the correct `IntersectionObserver` pattern to copy), and tablet-width layout shift is "poor" (CLS 0.327) from web-font swap reflowing the hero headline. Five smaller should-fix items (mobile video encode backwards vs desktop, a brand-name typo flowing from `upcoming_events.json`, three `rel="noreferrer"` vs the site's usual `noopener noreferrer`, an aria-label on a bare div, and a still-open registration-date VERIFY) are worth a pass but don't block. Everything else — content, accessibility structure, design tokens, links — is clean.
